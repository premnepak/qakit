🧭 Overview

What QAKit does and how it works

QAKit is a Chrome extension built specifically for QA engineers and developers who test web applications. It sits inside your browser and gives you instant access to inspection tools, screenshot capture, analytics monitoring, network request mocking, accessibility auditing, and much more — all without leaving the page you're testing.

QAKit works on any web application. Configure the allowed domains in Settings to restrict it to specific sites, or leave blank to enable it everywhere.

Pure launcher design: QAKit opens on the Home screen every time. Every tool is a tile on the Home grid — tap a tile to slide that tool in as a full-screen overlay. Tap ← Home in the top-left of any tool to return.

🗺 Navigation

How to move around QAKit

Opening a tool

Tap any tile on the Home grid. The corresponding tool panel slides in from the right, covering the Home grid. The QAKit header and footer remain visible at all times.

Going back to Home

Every tool panel has a green ← Home button in the top-left corner of the panel header. Clicking it slides the tool away and returns you to the Home grid.

Opening Settings

Click the ⚙ Settings button in the QAKit header bar. Settings slides in as a panel. Use ← Home to close it.

Tools that open in a new tab

JSON Viewer, Text Compare, and Help open in a new browser tab rather than inside the popup. This gives them more screen space for editing-style work.

Active tool highlights

When Inspect, Spacing, or Ruler is currently active on the page, its Home tile shows a green highlight border so you can see at a glance which tool is running.

🔍 Inspect & Measure

DOM inspection, spacing measurement, ruler and responsive preview

🔍 Element Inspector

Hover over any element on the page to see its CSS properties, dimensions, computed styles, test attributes, and accessibility role in a live tooltip. Click to pin the inspection to one element.

  • Displays element tag, ID, classes, test ID attribute
  • Shows box model: width, height, margin, padding, border
  • Highlights the element with a blue overlay
  • Keyboard shortcut: ⌘⇧Q / Ctrl⇧Q
📐 Spacing Inspector

Measures the exact spacing between elements. Hover to see margin and padding guides drawn on screen as coloured overlays (orange = margin, blue = padding).

  • Shows pixel values for all four sides
  • Hold Alt to measure distance between two elements
  • Keyboard shortcut: ⌘⇧Y / Ctrl⇧Y
📏 Ruler

Draws a measurement ruler on screen. Click and drag to measure the pixel distance between any two points on the page. Useful for verifying layout precision.

  • Shows horizontal and vertical pixel dimensions
  • Drag handles to resize the measured area
  • Click outside to dismiss
📱 Responsive Preview

Preview the current page at common device widths without leaving the browser. Choose from preset device sizes or enter a custom width.

  • Presets: Mobile (375), Tablet (768), Laptop (1280), Desktop (1440), Wide (1920)
  • Custom width input
  • Resizes the browser viewport in real time
  • QAKit remembers if you had this open and returns you to it next time
Mutually exclusive: Only one inspection tool can be active at a time. Opening Spacing automatically closes Inspect and Ruler, and vice versa.
Returns to Home: After triggering Inspect, Spacing, or Ruler from the Home tile, QAKit closes and the tool runs on the page. The next time you open QAKit you land on Home, not inside Page Kit.

📸 Capture

Screenshot and annotation tools

✏ Annotate

Draw on the current page before capturing. Add arrows, rectangles, text labels, and highlights to mark up what you're testing, then save as a PNG.

  • Freehand draw, shapes, text, arrows
  • Choose stroke colour and thickness
  • Undo / redo support
  • Save annotated screenshot as PNG
⬚ Region Screenshot

Capture a selected area of the page. Click and drag a rectangle over the area you want, release to capture. Result is copied to clipboard and a download toast appears.

  • Click and drag to select area
  • Auto-copied to clipboard as PNG
  • Toast notification with ⬇ Download button
  • Keyboard shortcut: ⌘⇧U / Ctrl⇧U
📄 Full Page Screenshot

Captures the entire page — not just the visible viewport — by auto-scrolling and stitching strips together. The final image is copied to clipboard and a download toast appears.

  • Auto-scrolls the page silently
  • Stitches all strips into one PNG
  • Copied to clipboard automatically
  • Toast with ⬇ Download button showing final dimensions
  • Keyboard shortcut: ⌘⇧K / Ctrl⇧K
🖼 Element Screenshot

Click any element on the page to capture just that element as a PNG — no background, exact bounds. Useful for capturing components in isolation.

  • Click to activate picker, then click any element
  • Captures element bounds precisely
  • Auto-copied to clipboard
  • Toast notification with ⬇ Download button
Screenshot toast: All screenshot actions show a dark toast at the bottom of the popup with a ⬇ Download button. The toast auto-dismisses after 10 seconds. The image is also copied to your clipboard so you can paste it directly into documents or bug trackers.
After a screenshot: QAKit closes while the capture runs. When you reopen it, you land on the Home screen — not inside any tool panel.

⚡ Analytics

Capture and inspect analytics events fired on the page

The Analytics panel captures data layer events, analytics calls, and WAE (Web Analytics Event) attribute clicks as they happen on the page. Events appear in a live feed as you browse.

Searching events

The search bar supports multi-criteria queries:

a, bComma or space separated = ORwae, ddl

-termMust excludewae -test

Filtering

  • Platform filter — show events from one platform only (GTM, GA4, DDL, etc.)
  • Event type filter — narrow by event type (page_view, click, etc.)
  • Search and filter settings are persisted between popup opens

Event actions

  • Click any event to expand and see its full payload
  • ⬇ Export — download all captured events as a JSON file
  • ⏸ Pause — stop capturing new events temporarily
  • 🗑 Clear Log — remove all captured events from the session
Analytics capture starts the moment the page loads, before QAKit is opened. Events are buffered in the background so you never miss a page load event.

⟷ Network Mock

Intercept and rewrite network requests in real time

Network Mock lets you intercept HTTP requests made by the page and return custom responses — without changing any code or running a proxy. Perfect for testing how the UI handles different API responses, error states, or edge cases.

Creating a rule

  1. Open the Network Mock panel
  2. Click + Add Rule
  3. Enter a URL pattern to match (supports wildcards: *)
  4. Choose the HTTP method (GET, POST, PUT, DELETE, or Any)
  5. Select the response type: JSON body, Status code, Redirect, or Block
  6. Enter the response body or status code
  7. Toggle the rule on and reload the page

Rule options

OptionDescription
URL PatternMatch string with optional * wildcards, e.g. */api/flights*
MethodGET, POST, PUT, DELETE, PATCH, or Any
Response TypeJSON body, Status code only, Redirect to URL, or Block entirely
Status CodeOverride the HTTP status (200, 400, 404, 500, etc.)
Delay (ms)Add artificial latency to simulate slow networks
Active toggleEnable or disable a rule without deleting it

Managing rules

  • Rules persist across page reloads and popup closes
  • Active rules are shown with a green dot on the Home tile
  • Toggle individual rules on/off without deleting them
  • Click the trash icon to permanently delete a rule
  • Import and export rules as JSON for sharing with your team
Reload required: Most rules take effect on the next page load, since requests are intercepted at the network level.

🏷 Headers Modifier

Inject, modify or remove HTTP request and response headers

Headers Modifier lets you add, override, or remove HTTP headers on every request made by the page. Useful for testing authentication tokens, CORS scenarios, feature flags passed via headers, or custom debugging headers.

Adding a header rule

  1. Open the Headers Modifier panel
  2. Click + Add Header
  3. Choose direction: Request (sent to the server) or Response (received from server)
  4. Choose operation: Add/Override or Remove
  5. Enter the header name (e.g. Authorization)
  6. Enter the value (for Add/Override)
  7. Toggle the rule active and reload the page

Common use cases

  • Inject a bearer token to test authenticated endpoints without logging in
  • Add custom feature-flag headers to test staged features
  • Remove security headers temporarily to test CORS handling
  • Override Accept-Language to test localisation
  • Simulate specific user agent strings
Header rules are applied at the declarativeNetRequest level — they're reliable and fast, and work with all requests including preload and prefetch.

🔬 Page Audit

Automated quality checks for links, images, spelling, performance, security and accessibility

Page Audit runs a comprehensive scan of the current page and scores it across four dimensions: Performance, Security, and Accessibility. The results are shown in a dashboard with an overall grade and clickable per-category scores.

Running an audit

  1. Navigate to the page you want to audit
  2. Open QAKit and tap the Page Audit 🔬 tile
  3. Click the green ▶ Run button
  4. Wait for the scan to complete (typically 5–30 seconds)
  5. Review the Overview dashboard, then click into Perf, Security, or A11y tabs

Overview dashboard

After a scan, the Overview tab shows:

  • Overall grade — A through F with a score out of 100
  • Perf / Security / A11y score chips — click any chip to jump to that sub-tab
  • Core Web Vitals — LCP, CLS, FCP, TTFB with pass/fail indicators
  • Issue summary chips — broken links count, broken images, spelling errors, accessibility issues, security issues

Sub-tabs

TabWhat it checks
OverviewScore dashboard, Core Web Vitals, issue summary
PerfLCP, CLS, FCP, TTFB, page weight, number of requests, render-blocking resources

A11yWCAG AA contrast failures, missing alt text, unlabelled form fields, missing landmarks, ARIA errors, heading hierarchy

Persistence and the last-scan banner

Audit results are saved automatically after every scan. The next time you open the Page Audit panel, you'll see a rich summary banner showing the last run's grade, scores, issue chips, and Core Web Vitals — regardless of whether you're on the same URL or a different one.

  • Click "View full results →" to load the full detailed results from that scan
  • Click × to dismiss the banner
  • Click ▶ Run to run a fresh scan on the current page

🔐 Session & Environment

Environment markers, cookies, local storage, and console errors

🏷 Environment Marker

Display a persistent visual badge on the page so everyone looking at a screen share or screenshot can instantly see which environment they're viewing (e.g. Staging, UAT, Dev, QA).

  • Variants: Bar (full-width top or bottom), Pill (corner), Ribbon (diagonal corner flag)
  • Positions: Top, Bottom (Bar), or any of the four corners (Pill / Ribbon)
  • Customise: label text, background colour, text colour, opacity
  • URL pattern matching: markers activate only on URLs matching a configured pattern
  • Multiple markers: add as many as you need, drag to reorder
  • Hide temporarily: double-click the marker on the page to hide it for the current page load
  • Drag to reorder: drag the grip handle (⠿) to reorder markers in the list
The opacity slider is draggable. The URL pattern input field is fully editable — click to place the cursor and type or select text normally.

🍪 Cookie Manager

View, search, edit, and delete cookies for the current domain.

  • Lists all cookies for the current URL with name, value, domain, path, expiry, and flags (Secure, HttpOnly, SameSite)
  • Filter — search by cookie name or value
  • ⊞ Expand / ⊟ Collapse — toggle all cookie rows expanded or collapsed
  • Click any cookie row to expand and see full details
  • Click the Edit (✎) button to modify a cookie's value, domain, path, or flags
  • Click the Delete (🗑) button to remove a cookie
  • Click ↻ Refresh to reload the cookie list

🗄 Local Storage

Browse and manage the localStorage keys for the current origin.

  • Lists all keys with truncated values — click any row to expand
  • ⊞ Expand all / ⊟ Collapse all — single toggle button cycles between expanded and collapsed state
  • 🔍 Search — filter by key name or value
  • Click the Edit button on any row to modify its value inline
  • Click the Delete button to remove a key
  • Click ↻ Refresh to reload
  • Long values are truncated in the collapsed view — expand to see the full content

⌗ Console Errors

Capture JavaScript errors and console output from the page's execution context.

  • Captures errors, warnings, and uncaught exceptions from page scripts
  • Shows the error message, source file, and line number
  • Click any error to expand and see the full stack trace
  • ↻ Refresh to reload the list
  • 🗑 Clear to remove all captured errors
  • Error count shown on the Home tile and in the page status strip
  • Configure which URL path prefixes are monitored in Settings → Console Error Paths
Console capture uses a MAIN-world injected script to intercept errors from page scripts — not just the extension context. This means it catches errors that the DevTools console would show you.

🔧 Utilities

Time, encoding, geolocation override, and page metadata

⏱ Time & Epoch

Two sub-tabs for time-related work:

World Clock (default)

  • Shows the current time in a set of pinned cities
  • Business hours dot indicator (green = business hours, grey = outside hours)
  • Pin your favourite cities, copy time with one click

Epoch & Timezone

  • Unix timestamp converter — paste any epoch value to see its human-readable date/time in UTC and local time
  • Date to epoch — enter a date and time to get the epoch value
  • Timezone converter — convert a time between any two timezones
  • Formats: ISO 8601, RFC 2822, relative time ("3 days ago")

🔐 Encode & Decode

Three encoding utilities in one panel:

🔑 JWT Decoder

  • Paste a JWT token to instantly see the decoded header, payload, and signature
  • Highlights expiry (exp), issued-at (iat), and subject (sub)
  • Shows a warning if the token is expired
  • Copy individual claims with one click

🔗 URL Encode / Decode

  • Encode a raw string to URL-safe format (%20, %2F, etc.)
  • Decode a URL-encoded string back to plain text
  • Full URL parser — break a URL into its scheme, host, path, query params, and fragment

📦 Base64 Encode / Decode

  • Encode any text or binary string to Base64
  • Decode Base64 back to plain text
  • Handles both standard and URL-safe Base64 variants

📍 Override Geolocation

Override the browser's navigator.geolocation API to return a custom location. Perfect for testing location-based features without physically being at that location.

  • City presets: Sydney, Melbourne, Brisbane, Perth, Auckland, London, New York, Singapore
  • Custom coordinates: enter exact latitude/longitude values
  • Accuracy override: set the reported accuracy in metres
  • Override is injected into the MAIN world so it affects page scripts, not just the extension
  • Active override shown in the Home tile hint and status strip
  • Toggle off to restore the real geolocation
  • Override persists across page loads until turned off
The geolocation override intercepts getCurrentPosition() and watchPosition() calls. Pages that cache location data may need a reload to pick up the override.

🔎 Page Metadata

Scans the current page and extracts all SEO and social metadata. Opens immediately when tapped from the Home grid and auto-runs the scan.

  • Core SEO: title, description, keywords, author, canonical URL, robots directive, viewport, charset, language
  • Open Graph: all og:* properties including title, description, image, type, URL, site name
  • Twitter Cards: all twitter:* properties
  • JSON-LD: all structured data blocks with type and summary
  • H1 tags: first five H1 elements on the page
  • Page stats: total links, images, and external scripts
  • All meta tags: complete list of every <meta> element

Use the ⎘ Copy button to copy all metadata as formatted text, or ⬇ Export to download as a .txt or .json file.

🛠 Developer Tools

JSON Viewer and Text Compare — open in a full browser tab

{ } JSON Viewer

A standalone JSON editor and tree explorer. Opens in a new browser tab for full-screen editing.

Data tab

  • 📋 Paste — paste from clipboard; auto-formats valid JSON
  • Format — pretty-print JSON with 2-space indentation + syntax colour
  • Minify — collapse to a single line
  • Sort keys — alphabetically sort all object keys recursively
  • Escape / Unescape — convert between raw and JSON-string representation
  • ⎘ Copy — copy current content to clipboard
  • ⬇ Download — save as .json file
  • Clear — reset the editor
  • Status pill shows validation state and node count
  • Typing in the Data tab live-syncs to Tree View

Tree View tab

  • Collapsible tree with [+] / [−] toggle boxes for every object and array
  • Colour-coded by type: ■ keys, ■ strings, ■ numbers, ■ booleans, ■ null
  • ⊞ Expand all / ⊟ Collapse all buttons
  • Sort keys / Copy / Download toolbar buttons
  • Search box — filters matching keys/values; auto-expands ancestors of matches
  • ↑ / ↓ Next / Previous buttons to cycle through search matches
  • Status shows match count (e.g. 3/12 matches)
  • Click any node to see its full value in the detail pane on the right
  • Resizable splitter between the tree and detail pane

⇄ Text Compare

A side-by-side text diff tool. Opens in a new browser tab. Both panes are always editable — paste text into either side and the diff highlights update live.

Live diff

  • Live mode (on by default) — diff updates automatically 300ms after you stop typing or pasting
  • Uncheck Live to only compute the diff when you click ▶ Compare
  • Both panes always remain editable — the diff is shown as a colour overlay on top of the text

Diff highlighting

  • Red background — lines removed from the original (left pane)
  • Green background — lines added in the revised version (right pane)
  • Word highlight — within changed lines, specific added/removed words are highlighted in deeper red/green

Copy actions

  • → Copy to right button — appears on each changed/removed line in the left pane; copies that line to the right pane
  • ← Copy to left button — appears on each added/changed line in the right pane; copies that line to the left pane
  • Shift+click multiple copy buttons to select several lines, then use the floating bar to → Copy all to right or ← Copy all to left

Minimap

  • The right edge of the compare view shows a VS Code-style minimap column
  • Green ticks = added lines, Red ticks = removed lines, Amber ticks = changed lines
  • A viewport rectangle shows your current scroll position
  • Click any tick to jump to that change

Toolbar options

OptionEffect
Ignore whitespaceTreats lines differing only in whitespace as equal
Ignore caseCase-insensitive comparison
Word highlightHighlights word-level differences within changed lines
⇄ SwapSwaps left and right pane contents
ClearEmpties both panes

Jump strip

Below the comparison area, a row of labelled change tags (e.g. +R:3 −L:7 ~L:12) lets you jump directly to any specific change. Click any tag to scroll both panes to that change with a flash highlight.

Both panes scroll in synchrony — scrolling either pane moves the other to the same line level, keeping the two sides aligned.
The workspace is auto-saved. Your pane contents, split ratio, and options are restored the next time you open Text Compare.

⚙ Settings

Configure QAKit for your team and workflow

🎨 Appearance

Toggle between ☀ Light mode and 🌙 Dark mode with a single button. The theme applies immediately and is saved automatically.

🌐 Allowed Domains

Comma-separated URL patterns that QAKit activates on. Use * as a wildcard. Leave blank for all domains. Example: *.myapp.com, *.staging.myapp.com

📡 Analytics Providers

Choose which analytics platforms to monitor. WAE attribute capture is always on. Toggle GTM, GA4, DDL, Adobe, Tealium, Meta Pixel, Floodlight, and Segment individually.

📊 Analytics Filter

Set a default search filter that pre-populates the Analytics search box. Useful if you always want to filter to a specific event type or platform.

🔍 Test Locator Attribute

The attribute name used for test IDs on your application (e.g. data-testid, data-qa). The Element Inspector highlights this attribute in its output.

🗄 Local Storage Keys

Comma-separated key names to track. Leave blank to show all keys. Useful if your application has many LS keys and you only care about a specific subset.

🍪 Cookie Filter

Comma-separated cookie names to show in the Cookie Manager. Leave blank to show all cookies.

🖥 Console Error Paths

Comma-separated URL path prefixes. Console errors from scripts at these paths are captured. Default: /scripts/,/blocks/

Save and Reset

  • Click 💾 Save Settings to persist all changes
  • Click ↺ Reset to Defaults to restore all settings to their original values
  • Settings are stored in chrome.storage.local — they persist between browser sessions but are local to your browser

Export / Import

  • ⬇ Export settings — download your configuration as a .json file for backup or sharing with teammates
  • ⬆ Import settings — load a previously exported settings file
